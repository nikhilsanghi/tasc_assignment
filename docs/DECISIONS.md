# DECISIONS.md — decision log (read before any architectural change)

Format: **ID · Decision · Alternatives rejected · Why · One-liner**. Code comments cite IDs (`# D-07`). Append new entries as D-44+; never edit the substance of an existing entry — add a superseding entry and cross-reference.

## Original decisions (v1.0) — amendments from v1.1 noted inline

- **D-01** Rubric-compiled hybrid architecture · vs monolithic LLM ranker; plain two-stage funnel · Monolithic: irreproducible, position-biased, unauditable, dies at scale; plain funnel: guidance can't reach stage 1 · *"The LLM legislates once; deterministic code is the court."*
- **D-02** Deterministic scorer is sole ranking authority; LLMs never assign final scores · vs LLM-as-ranker · Reproducibility, auditability, score-clustering avoidance; injected text has no representational path to weights · *"Same input, same ranking, every time — that's a compliance feature."*
- **D-03** Policy/rubric separation with immutable `policy.json` · vs single mutable config · Steerability without governance is a liability in hiring; banned criteria can't be steered away · *"Users steer weights, never the guardrails."*
- **D-04** Free-text steering via whitelisted rubric-diff ops · vs free-form prompt passthrough · Makes steering testable; mirrors query-understanding systems (free text → structured attributes) · *"Guidance compiles to five verbs or it's rejected out loud."* (v1.1: five ops — `set_top_k` added, D-37; concept grounding, D-20.)
- **D-05** Rubric echo-back confirmation before scoring · vs silent application · Catches misinterpretation; transparency = trust · *"The system says what it heard before it acts."*
- **D-06** Grounding rule: citations must be verbatim substrings, critic-verified · vs free-generated explanations · Kills hallucinated skills mechanically, not rhetorically · *"Evidence or it didn't happen."*
- **D-07** Reranker = flagged second opinion, never authority · vs LLM rerank as final order · Captures LLM judgment; disagreement is information for the human · *"The AI gets a vote, not a veto."* (v1.1: single pass, flags only — see D-27.)
- **D-08** Sequential stages-as-functions, no framework · vs CrewAI/LangGraph/concurrent agents · Sequential is more interpretable for high-stakes decisions; frameworks add deps and failure modes · *"Eight functions, one arrow, zero magic."*
- **D-09** Prompt-injection guards are in scope · vs "it's just a take-home" · The headline feature (free text → policy) IS the attack surface; profile text is untrusted; a public link guarantees probing · *"The headline feature is also the attack surface — so it is defended."*
- **D-10** Duplicates flagged & clustered, never deleted · vs dedup-and-drop · 22/26 dup groups have conflicting facts; deletion destroys information; conflicts become clarifying questions · *"The mess is signal."* (v1.1 counts, D-22.)
- **D-11** Dirty fields parsed with confidence flags surfaced in UI · vs silent cleaning · The assignment explicitly probes messy-data handling; recruiters need to see uncertainty · —
- **D-12** Missing data → neutral 0.5 + flag, not zero · vs zeroing · Zeroing silently buries strong-but-incomplete profiles; flags convert uncertainty into questions · *"Absence of evidence isn't evidence of absence — it's a question."* (v1.1: also governs hard filters on unparseable values, and paired with the insufficient-data strip, D-24.)
- **D-13** Four-fifths implemented as a labeled demonstration on a country proxy · vs full "bias audit" claim; vs skipping · Data has zero protected attributes — claiming a real audit would be theater; demonstrating the mechanism + naming the production requirement is stronger · *"The audit machinery is built; what it can measure on this data is stated honestly."* (v1.1 placement, D-31.)
- **D-14** ESCO/O*NET described, not built · vs integrating a 13,939-skill ontology · 113-token vocab; alias table + similarity cache achieves the goal; an ontology at this scale is cosplay · —
- **D-15** No vector DB / RAG / fine-tuning at n=120 · thresholds: embedding+ANN retrieval stage at ≥10⁴ candidates; outcome-data fine-tuning when labels exist; controls layer unchanged throughout · *"The seams are placed so scale swaps the retrieval stage, not the governance."*
- **D-16** Similarity precomputed offline into committed JSON; zero runtime embedding calls · vs runtime embedding API / deployed model · Deterministic, fast, free, fits serverless size limits · — (v1.1: pinned model + provenance header, D-33.)
- **D-17** Vercel + thin static frontend + Python serverless; key server-side; access code + token caps · vs AWS (over-engineered) and vs static-page-with-key (key theft via DevTools) · Dumb frontend keeps all logic testable in `/core` · *"A static page calling the API ships the key to strangers."* (v1.1: deploy is a stretch goal, D-29.)
- **D-18** Env-switchable model routing; prompt caching on shared prefixes · vs one hardcoded model · Cost/latency literacy; K parallel calls dominate spend · — (v1.1: both env vars default to one model, D-25; caching made real, D-26.)

## v1.1 decisions (from the pre-implementation review)

- **D-19** Guard validates the **post-renormalization** weight vector; op-level bound violations are rejected (`policy_violation`), emergent post-renorm violations are clamped to the bound with proportional redistribution and disclosed in `adjustments[]` · vs per-op validation only (v1.0) · Per-op checks were decorative: `availability→0.60` + four dimensions→0.0 + one→0.05 renormalizes to 0.60/0.65 ≈ 0.92 while every op passes; explicit violations deserve rejection, emergent ones deserve disclosure, neither deserves silence · *"The pre-implementation review found the guard was decorative — so it moved after the math."*
- **D-20** The compiler **grounds free-text concepts into concrete match terms** (`match_terms[]` + `fields[]`) and the scorer matches deterministically (cascade for `skills`, substring elsewhere); boost fields extended to certifications, education, headline, extra_curriculars · vs matching concepts through the precomputed similarity cache (v1.0) · The cache only spans known skill tokens — an arbitrary phrase like the PDF's own "client-facing experience" is on neither axis, so boosts could never fire; grounding at compile time keeps the LLM decision one-shot and the runtime deterministic · *"The LLM translates intent into searchable terms once; the scorer never guesses."*
- **D-21** Availability parse table enumerates all observed formats; `N days` passes through · vs weeks/months only (v1.0) · Day-denominated formats are 43/120 rows and would all have fallen to the neutral path · —
- **D-22** Duplicate key = whitespace-normalized headline+skills; conflicts measured on canonical values (location → city/country; other fields → whitespace-collapsed casefold); asserted facts 26 groups / 69 rows / **22 conflicting** / pool 77 (raw 23/61 also recorded for transparency) · vs raw byte-identical keys and raw-string conflict comparison · The Normalizer is required to clean whitespace; clustering after cleaning is correct and catches the file's most obvious duplicate (C106≈C014); comparing conflicts on canonical values avoids flagging `Riyadh,Saudi Arabia` vs `Riyadh, Saudi Arabia` as a conflict and asking a silly question · *"Clean first, then cluster — and the count goes up, which is the point."*
- **D-23** `-` is treated as null; HTML markup stripped and flagged; mojibake, reversed year ranges, and headline/field contradictions flagged; citation containment runs on normalized text · vs treating `-` as content · `-` is the dominant null marker (44/66/44 rows per column); unhandled it pollutes prompts and data-quality scores · —
- **D-24** Profiles with data-quality < 0.5 or empty skills go to a separate insufficient-data strip, never interleaved · vs ranking them at ~50 under D-12 · Neutral-0.5 is right for a missing *field*, wrong for a missing *profile*; surfacing them separately is the honest recruiter product ("needs sourcing follow-up") · *"Half a score for half a profile — shown, not ranked."*
- **D-25** One model, `claude-sonnet-5`, for all LLM agents; no `temperature` parameter; structured outputs via `messages.parse()`; `MODEL_REASONING`/`MODEL_FAST` retained as a documented routing seam · vs two-tier routing on older model IDs (v1.0) · Current Sonnet is materially stronger on structured work; the model family rejects sampling params and determinism never lived in the LLM anyway (D-02); the seam stays so the cost lever is one env var away · *"Determinism is the scorer's job; the model's job is to be right."*
- **D-26** Prompt caching made real: ≥1024-token stable system prefix with `cache_control`, analyze #1 fired alone then the rest through a pool of 4, live assertion of `cache_read_input_tokens > 0` · vs markers on a short prefix fired all at once (v1.0) · Below the model's minimum prefix the markers silently no-op, and simultaneous fan-out writes the cache K times and reads it zero times · *"Fire one, let the cache land, then fire the rest."*
- **D-27** Reranker is a single listwise pass emitting disagreement flags only; forward+reversed and multi-run τ are documented, not built · vs v1.0 fwd+rev aggregation · Halves latency and spend for a stage whose designed output is flags; position-bias mitigation is a stated seam · —
- **D-28** Runtime deps = `anthropic` (pinned) + `pydantic>=2` (the SDK's own dependency, listed explicitly); pandas/numpy/sentence-transformers are dev-only; normalizer output committed as `candidates_normalized.json` + `roles_normalized.json` · vs pandas in the runtime bundle · Cold-start tax on the first request for zero runtime benefit · —
- **D-29** *(layout superseded by D-46 — frontend now in `public/`)* Static files at repo root, `/api` beside them, `vercel.json` with `maxDuration`+`includeFiles`, Phase 0 hello-world deploy spike; success = local end-to-end, public deploy = stretch · vs deciding layout in Phase 5 and gating success on the live URL (v1.0) · Packaging/timeout risk retired on day one; a hosting hiccup cannot fail the project by its own definition · —
- **D-30** Clarifying-question composition: exactly 3, ≥2 role-fit gaps, ≤1 data-conflict/relocation; overflow auto-questions render under flags · vs unspecified merge · Heavily flagged candidates could otherwise get three hygiene questions and zero gap-closing ones — a literal miss on PDF output 4 · —
- **D-31** Four-fifths computed in `run_evals.py` (README table for all roles) + one line in the export; no UI integration · vs full UI panel · Demonstration value delivered at a fraction of the plumbing · —
- **D-32** Golden set = 2 roles × ~12 candidates, 0–3 graded; labeling sheet generated in Phase 1 and handed to the Owner at that gate; κ cases drawn from the same labels · vs 3×15 labeled in Phase 6 · Slowest human task moved off the critical path; at this n the metrics are equally anecdotal · —
- **D-33** Embedding model pinned (name + revision); `skill_similarity.json` carries a provenance header copied into `audit.json`; a test asserts the header matches the pinned constant · vs "e.g. all-MiniLM" · The one unaudited input in an otherwise fully audited pipeline · —

- **D-35** Live groundedness gate passes on 2-of-3 consecutive runs; persistent failures become data flags; containment normalization includes HTML-strip + Unicode NFC · vs a 100% single-run hard assert · LLM output is non-deterministic across calls; the data (C120 HTML, C124 mojibake) guarantees brittleness · *"A citation that can't be grounded becomes a flag — the failure mode is the feature."*
- **D-36** No personal information and no effort/time estimates in shipped files; `private/` (gitignored) holds working notes, the labeling sheet, the Loom script and prep material; the master brief ships · vs committing prep material (v1.0) · Prep material is not part of the deliverable; the brief ships as the artifact that directed the build · —

- **D-38** Code concision enforced mechanically by `scripts/check_style.py` (file/function length, forbidden deps in runtime paths, forbidden terms) at every gate · vs prose guidance only · Rules that aren't checked drift · —
- **D-39** Rejection UX split: `policy_violation` vs `not_supported` (with `closest_supported` hint) vs `injection_suspected` · vs one undifferentiated rejection · Benign-but-unsupported guidance must degrade gracefully, not look like a failure of the headline feature · —
- **D-40** Critic is deterministic Python, not an LLM · vs LLM critic (v1.0 §4.1) · The grounding check is substring containment — code does it exactly, instantly, for free; v1.0 §2.3 already said "mechanically"; halves `/api/analyze` latency to two LLM calls · *"The critic is code. Evidence is checked, not judged."*
- **D-41** `skill_aliases.json` authored in Phase 0; similarity cache computed over alias-expanded atomic tokens; tokenization for all skill facts = comma-split, strip, casefold · vs unowned alias file and cache over raw compounds · Compounds embed poorly against atomic tokens; the cache would have needed rebuilding · —
- **D-42** LLM call configuration per stage: compiler adaptive thinking + effort `medium` + `max_tokens` 4000; analyst `thinking={"type":"disabled"}` + effort `low` + 2500; reranker adaptive + `medium` + 3000; judge (evals) adaptive + `medium` + 2000; `stop_reason != "end_turn"` or empty parse → `LLMOutputError` → HTTP 502 · vs leaving `thinking` unspecified with 1200–1800 caps · This model family thinks by default and thinking is billed inside `max_tokens`, so tight caps would truncate structured JSON and look like a flaky gate; the analyst is an extraction task run K times under a latency budget, so it runs without thinking · —
- **D-43** Identity hygiene in shipped artifacts: git author set to a neutral name + noreply email before the first commit; only the clean production alias `https://<project>.vercel.app` (name-free project name) is ever recorded; absolute machine paths in pasted output are redacted to `<repo>`; `check_style.py` hard-fails on home-directory absolute paths (the macOS user-folder prefix followed by an account name) and on email patterns in shipped files, plus the Owner's private term list · vs relying on the term list alone · Deployment URLs, tracebacks, and git metadata are the three channels through which a name leaks into a repo that is otherwise clean · —
- **D-46** Repo layout: `api/` (platform requirement) · `core/` (all logic) · `data/` · `docs/` (brief, plan, decisions, test plan, results) · `prompts/` · `public/` (static root) · `scripts/` · `tests/`; only `CLAUDE.md`, `README.md` and config files sit at the repo root; the brief is renamed `docs/MASTER_BRIEF.md` · vs planning documents and CSVs loose at the repo root · A reviewer's first impression is the root listing; grouping docs and data and serving the frontend from Vercel's conventional `public/` reads as an engineered repo rather than a scratch folder, and costs one mechanical move in Phase 0 · —
- **D-47** Protected-attribute proxy scan uses a dedicated `policy.proxy_scan_terms` list after masking `proxy_scan_mask` phrases; flag-only; `banned_terms` stays the Guard's list for recruiter-typed boost terms · vs scanning free text with `banned_terms` · Measured: `banned_terms` would flag 10 real profiles — 7 for "United *Arab* Emirates University" and 3 for mentoring a "*women*-in-tech program" — none of which is a protected-attribute disclosure; the dedicated list flags zero rows on this dataset, which the README states plainly · *"A proxy detector that flags a university name is a bias generator, not a bias guard."*
- **D-48** Deployment hygiene: `.vercelignore` (secrets, `private/`, non-runtime dirs) and a placeholder `public/index.html` exist from Phase 0; the spike asserts that `/.env`, `/private/*`, `/data/*` and `/api/_shared` are 404 · vs relying on `.gitignore` · The Vercel CLI uploads everything not in `.vercelignore`, and with an empty `public/` the repo root becomes the public static directory — every source file, the private notes and `.env` would have been served until Phase 5 · —
- **D-44** SDK version pinned to `anthropic==0.124.0` (installed fresh in Phase 0, verified `client.messages.parse` and `ParsedMessage.parsed_output` both exist with the expected signature — `output_format`, `output_config`, `thinking`, no required `temperature`); `pydantic>=2` per the SDK's own dependency · vs an unpinned range · A structured-output helper (`core/llm.py`) needs a fixed contract; pinning the exact version installed and tested removes drift between dev and deploy · —
- **D-49** `headline_experience_conflict` fires only when a headline-stated year count differs from the `experience_years` field by **more than 1 year** · vs any non-equal match · Measured: on the real data a naive any-mismatch rule also fires on C122 ("5 years" vs field `6`) — which the brief calls out separately as a *truncated headline*, not a contradiction — while only C128 ("15 years" vs field `1`, a 14-year gap) is named as the intended contradiction fact; a >1-year tolerance isolates exactly `{C128}` and is the smallest change that does so · —
- **D-45** `data/skill_aliases.json` transcribed verbatim from plan Appendix A.4: 26 `expand` entries (compound → atomic tokens, role-side and candidate-side merged, 4 exact duplicates collapsed) and 6 `synonyms` entries; all 18 candidate-side compound keys verified present in the real 113-token vocabulary. Of the 17 unmatched role tokens, 14 now resolve (8 via `expand`, 6 via `synonyms`); 3 are deliberately left unmapped — `rest apis` (tier-3 semantic test pair, must not be aliased), `kafka` (zero-match control), `saas product experience` (left to tier 3) · vs inventing additional mappings to raise the match rate · The appendix seed was pre-checked against the real vocabulary; adding unlisted mappings would risk matching tokens that don't actually appear together in the data · —
- **D-50** Phase 0's `api/_shared.dispatch` implements only the access check (401) and a generic `Exception` -> 500 fallback; the `LLMRateLimited` -> 429 and `LLMOutputError` -> 502 branches named in plan §1 are added when `core/llm.py` first exists (Phase 2), extending `dispatch` rather than rewriting it · vs creating stub exception classes in a not-yet-planned `core/llm.py` during Phase 0 to satisfy the full contract early · Phase 0's file list does not include `core/llm.py`; inventing it early to hold two exception stubs would improvise outside the phase plan for no Phase-0-visible behavior (health has no LLM path) · —
- **D-51** `api/_shared.py` exposes a shared `APIHandler(BaseHTTPRequestHandler)` base class instead of the plan's `make_handler(handle, methods=...)` factory function; each `api/<name>.py` subclasses it with a literal `class handler(APIHandler): handle_fn = staticmethod(handle); methods = (...)` statement instead of `handler = make_handler(...)` · vs the plan's factory-function pattern · Measured via `vercel build` A/B probes: Vercel's local Python function detector recognizes a literal top-level `class handler(...)` statement via static analysis regardless of what the file imports (confirmed even combined with `sys.path.insert` and a `core.paths` import), but silently reports "no Serverless Functions" for `handler = make_handler(...)` (a runtime-assigned class) as soon as the file has any import reaching outside `api/` — the detector appears to fall back to executing/resolving the module for non-literal assignments, and that resolution fails in its scan context. All shared dispatch/response logic still lives in one place (`APIHandler`); only the per-endpoint binding changed from a function call to a one-line subclass · —
- **D-52** Fixed a pre-existing `.gitignore` ordering bug: a blanket `.env*` pattern (tooling section) sat *after* the `!.env.example` negation (secrets section), silently re-excluding the shipped `.env.example` template; added a second `!.env.example` after the later `.env*` line · vs leaving it, which would have shipped a repo with no `.env.example` despite step 3 producing one · gitignore negations only win over patterns that appear *before* them; the later duplicate line was clobbering the earlier one · —
- **D-53** `core/normalizer.py` split into three files to stay under the 250-line/file limit: `core/normalizer.py` keeps the pure per-field parsing functions (`clean_text`, `parse_experience`, `parse_notice`, `parse_location`, `split_skills`, `norm_tokens`, `seniority_level`, `headline_experience_claim`, `dup_key`, `canonical_value`, `data_quality`), `normalize_roles`, and the `__main__` writer; `core/normalizer_tables.py` holds the lookup tables/compiled patterns (word numbers, country aliases, seniority ladder, HTML/mojibake/year-range regexes); `core/normalizer_records.py` holds `normalize_all` and its private per-record assembly helpers, importing the pure functions from `core.normalizer` (one-directional — `core/normalizer.py` only reaches into `normalizer_records` inside its `if __name__` guard, so there is no load-time circular import) · vs one 294-line file · The function/table/record-assembly concerns are already naturally separable; splitting along those lines needed no behavior change · —
- **D-54** Seniority-ladder keyword boundaries use `(?<!\w)pattern(?!\w)` lookarounds instead of `\bpattern\b` · vs the plan's literal `\bsr\.` escaping example, generalized to all keywords with a trailing `\b` too · A trailing `\b` can never match right after a keyword ending in punctuation (`sr.`) followed by whitespace, since `\b` requires one side to be a word character and both `.` and a following space are non-word — caught by the `"Sr. DevOps Engineer"` test case, which returned 1.0 (mid, via `engineer`) instead of 1.5 (mid-senior, via `sr.`) until fixed; lookarounds correctly require "not a word character on either side" regardless of whether the keyword itself ends in a word character · —
- **D-55** Fixed a Phase 1 bug found while building the Phase 3 seniority subscore: `normalize_roles` computed a role's `seniority_level` by running the *candidate* keyword ladder against the role's job **title** (`seniority_level(row["title"], None)`), instead of directly mapping the CSV's own `seniority` column (Junior/Mid/Mid-Senior/Senior) via brief Appendix A.5's explicit string→number table · vs leaving it, since it happened to be right for some roles by coincidence · Measured: wrong for 3 of 10 roles — R002 ("Junior", title has "Representative" → tier-4 "mid" 1.0 instead of 0.0), R006 ("Mid-Senior", title has "Manager" → tier-1 "senior" 2.0 instead of 1.5), R008 ("Senior", title has "Engineer" → tier-4 "mid" 1.0 instead of 2.0); fixed with a direct `ROLE_SENIORITY_LEVEL` lookup in `core/normalizer_tables.py`, `data/roles_normalized.json` regenerated · —
- **D-56** `core/scorer.py` split into `core/scorer.py` (subscores, composite, `score_candidate`, `collapse_dups`, `score_all`) and `core/scorer_filters.py` (hard-filter logic, including the `MENA` constant since the filter code is its only other user) to stay under the 250-line/file limit — same reasoning as D-53's normalizer split · vs one file · `scorer.py` imports `apply_hard_filters` and `MENA` from `scorer_filters.py`, which depends only on `core.skills`, so the dependency is one-directional and there is no circular-import concern · —
- **D-57** `public/app.js`'s `api()` helper omits the `body` field entirely for GET/HEAD requests instead of always JSON-stringifying one · vs always passing a body · Caught live in the browser during Phase 5 manual testing: the browser's `fetch()` throws `TypeError: Request with GET/HEAD method cannot have body` immediately, before the request is even sent — this broke the role dropdown (`GET /api/health`) on first load. - **D-58** Phase 6 added `core/evals.py` (pure metric functions — `ndcg_at_k`, `recall_at_k`, `kendall_tau`, `mean_rank`, `cohens_kappa`) and `scripts/eval_live.py` (the judge `Judgement` schema + `judge_candidate`, the injection-suite section, the reranker-overlap helper), neither named in the plan's file list, alongside `scripts/run_evals.py` · vs cramming everything into one `run_evals.py` · Two reasons: (1) `tests/test_evals.py` needs to import the metric functions directly for hand-example tests, so they need a home outside the script; (2) `run_evals.py` alone would exceed the 250-line limit with all 8 report sections inline — same reasoning as D-53/D-56's splits, applied proactively this time instead of after hitting the ceiling · —
